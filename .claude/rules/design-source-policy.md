# 디자인 기준 정책

**디자인 의도의 Source of Truth는 Figma, 코드에서 쓰는 토큰 계약은 `apps/web/src/_app/globals.css`의 `@theme`다.**
둘이 어긋나면 임의로 한쪽을 고르지 않고 차이를 확인해 동기화한다.
토큰 값과 컴포넌트 명세의 진입점은 `docs/design-system/README.md`, DO/DON'T는 `docs/design-system/guidelines.md`.

---

## 1. 우선순위

```
Figma 시안                ← 디자인 의도
        ↕ 대조·동기화
globals.css (@theme)      ← 구현에서 쓰는 토큰 계약
docs/design-system/       ← 두 소스를 사람이 읽게 정리한 문서 + 결정 근거
PNG 캡처                  ← 참고용. 값의 근거로 쓰지 않는다
```

문서 값이 어긋났다면 무시하지 말고 **어느 쪽이 갱신되지 않았는지** 확인해 문서를 맞춘다.

## 2. ⚠️ Figma MCP가 만들어 준 코드를 붙여넣지 않는다

Figma MCP(figma · figwright)는 선택한 노드의 React/Tailwind 코드를 만들어 줄 수 있다. **그대로 쓰지 않는다.**

- FSD 레이어 구조를 모르고 한 파일에 쏟아낸다
- 우리 공용 컴포넌트(`Button` · `Icon` · `TopAppBar` · `Drawer` …)를 모르고 일회성 마크업을 만든다
- 토큰 대신 **원시 색상값**을 박는다
- `rounded-8` 같은 커스텀 스케일을 모르고 Tailwind 기본 이름(**이 프로젝트엔 없는 이름**)을 쓴다

**생성 코드는 "시안에 무엇이 있는지" 읽는 용도로만 쓴다.** 수치는 design context(레이아웃·변수)에서,
구현은 우리 컴포넌트와 토큰으로 한다.

## 3. PNG에서 픽셀값을 역산하지 않는다

캡처를 재서 `gap-[29px]` 같은 값을 만들지 않는다. 정확한 값은 **Figma 또는 토큰**에서 가져온다.
PNG로 확인해도 되는 것: 요소의 **존재 여부 · 순서 · 정렬 · 상태 구분**. 수치는 안 된다.

## 4. 시안과 구현을 비교할 때 보는 축

"2px 다름"을 수백 개 뱉지 않도록 아래 6개만 본다.

| 축                  | 비교 대상                                       |
| ------------------- | ----------------------------------------------- |
| ① **토큰**          | Figma 변수 ↔ `@theme` / Tailwind 클래스         |
| ② **공용 컴포넌트** | Figma 컴포넌트·variant ↔ `shared/ui` variant    |
| ③ **구조**          | 요소 존재 여부 · 순서 · 정렬                    |
| ④ **상태 커버리지** | 빈 / 로딩(skeleton) / 에러 / 비활성 / 권한 없음 |
| ⑤ **문구**          | 레이블 · 플레이스홀더 · 에러 메시지             |
| ⑥ 수치              | **토큰이 있는 경우에만**                        |

**④가 가장 값어치 있다.** 시안에 상태 프레임이 있는데 구현에 없으면 "다르다"가 아니라 **"기능이 없다"**이다.

## 5. 소스가 충돌하면 결정하지 않는다

기획(`docs/features/…`) · Figma · API 계약이 서로 다르면 **임의로 고르지 않는다.**
작업 문서의 `확인 필요`에 적고 사용자 판정을 받는다. 여기서 내가 고르면 그게 제품 결정이 된다.

**문구도 마찬가지다.** 시안·기획에 없는 문구를 지어내거나, 있는 문구를 요청 없이 바꾸지 않는다.

## 6. 미확정 토큰은 하드코딩하지 않는다

- **spacing**은 Figma 공통 토큰이 없다 → Tailwind 기본 스케일에서 가장 가까운 값
- **shadow/elevation**은 정의가 없다 → 새로 추가하지 않는다
- 기본 스케일로 표현이 안 되는 시안 고유 수치는 Figma 실제 값을 근거와 함께 남기고, 재사용되는지 확인한 뒤 토큰 승격을 결정한다
- `@theme`에 없는 값을 임의 이름의 토큰으로 추가하지 않는다

## 7. 시안이 없는 화면

- **"시안 없음"을 작업 문서에 명시한다** (확인한 날짜와 함께)
- 기존 화면·컴포넌트 패턴을 그대로 따르고, 개선 판단을 하지 않는다
- 나중에 시안이 생기면 별도 작업에서 대조한다
