# 작업 기록 규칙

**기록은 남기되, 의식(儀式)은 최소로.** 폴더를 상태별로 옮기지 않고, 전역 번호도 관리하지 않는다.

---

## 1. 어디에 쓰나

| 작업                                                      | 위치                                  | 누가 만드나                                    |
| --------------------------------------------------------- | ------------------------------------- | ---------------------------------------------- |
| 기능 (`feat`) — 화면·사용자 행동                          | `docs/features/{기능ID}/`             | `feature-planner` → `test-scenarios` → `tdd-*` |
| 기능이 아닌 작업 — 하네스·업그레이드·리팩터·네이티브·버그 | `docs/work/{TYPE}-{이슈번호}-{설명}/` | `ai-plan`                                      |
| 작업 중 발견한 범위 밖 문제                               | `docs/work/backlog.md` 에 한 줄       | 발견한 사람/AI                                 |

- `TYPE`: `INFRA`(하네스·빌드·CI·의존성) · `REF`(구조 리팩터, 동작 불변) · `NAT`(apps/native) · `FIX`(버그·시안 불일치)
- **번호는 GitHub 이슈 번호**를 쓴다 — 브랜치 이름(`chore/#123/…`)과 같다. 이슈가 아직 없으면 `{TYPE}-{YYMMDD}`로 시작하고, 이슈가 생기면 폴더 이름을 바꾼다
- `.local-docs/`는 개인·다른 에이전트용 작업 공간이다. 여기서 말하는 **기록은 커밋되는 `docs/`** 에 남긴다

## 2. `docs/work/{ID}/` 안의 파일

| 파일            | 내용                                                       | 필수 |
| --------------- | ---------------------------------------------------------- | ---- |
| `plan.md`       | 목표·비목표, 영향 범위, 순서 체크리스트, 리스크, 검증 방법 | ✅   |
| `retrospect.md` | 무엇이 예상과 달랐나, 다음에 다르게 할 것 (몇 줄이면 된다) | 선택 |

- 상태는 **`plan.md` 첫 줄**에 적는다: `상태: 계획 | 진행 | 완료 (YYYY-MM-DD)`. 폴더는 옮기지 않는다
- 완료 후에는 내용을 고치지 않는다. 후속이 필요하면 새 ID로 연다

## 3. 범위 밖 문제는 그 자리에서 고치지 않는다

작업하다 범위 밖의 문제를 발견하면 **고치지 않고 `docs/work/backlog.md`에 한 줄로 남긴다.**

```markdown
- [ ] 2026-11-25 · create-meeting 스텝들이 draft 전체 구독 → 리렌더 과다 (state-convention §3) · 발견: INFRA-harness
```

범위 밖 수정을 끼워 넣으면 검증에서 "무엇 때문에 깨졌는지" 구분이 안 된다.
작업을 막는 문제라면 사용자에게 알리고 승인을 받은 뒤 처리한다. 어떤 항목을 GitHub 이슈로 올릴지는 사용자가 정한다.

## 4. 끝나면 확정 사항을 기준 문서로 올린다

작업 기록은 동결되지만, **결정은 기준 문서에 살아 있어야** 다음 작업이 안다. 이 단계를 건너뛰지 않는다.

| 확정된 것                      | 올릴 곳                                                           |
| ------------------------------ | ----------------------------------------------------------------- |
| 새로 합의한 코드 규칙          | `.claude/rules/` (+ 사람용이면 `docs/conventions/`)               |
| 토큰·컴포넌트 규격             | `docs/design-system/`                                             |
| 화면 명세·검증 기준            | `docs/fe-implement-spec/` 또는 `docs/features/{ID}/spec-fixed.md` |
| 명령·도구가 새로 생기거나 바뀜 | `CLAUDE.md` (Commands · Follow-ups 표)                            |
