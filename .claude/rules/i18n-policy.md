# i18n 정책 — 하지 않는다

**이 프로젝트는 한국어 단일 언어다. 국제화(i18n)를 도입하지 않는다.**

규칙이라기보다 **"이 제안을 그만하라"** 는 정책이다.
AI는 한글이 하드코딩된 코드를 보면 반사적으로 i18n을 제안하는데, 여기서는 매번 잘못된 제안이다.

---

## 하지 않을 것

- ❌ `next-intl`·`react-i18next` 등 i18n 라이브러리 도입 제안
- ❌ 한글 문자열을 `messages.ts` / `locales/ko.json`으로 추출하자는 제안
- ❌ 리뷰·회고의 개선 항목에 "한글 하드코딩 → i18n 필요"를 적는 것
- ❌ 스펙의 Out of Scope에 "다국어 지원"을 적는 것 (애초에 검토 대상이 아니다)
- ❌ `t('key')` 형태의 래퍼를 "나중을 위해" 미리 만드는 것

> **한글 하드코딩은 그 자체로 코드 스멜이 아니다.**

## 해도 되는 것

- ✅ UI 문구를 컴포넌트 안에 한국어로 직접 쓴다
- ✅ 기획이 바꿀 문구가 여러 곳에 반복되면 **상수로** 뽑는다 — i18n이 아니라 `constants-convention.md`의 판단이다

상수로 뽑을 때는 키만 영문, 값은 한글 그대로 둔다.

```ts
export const LOGIN_REQUIRED_MESSAGE = '로그인이 필요합니다'; // ✅
t('auth.loginRequired'); // ❌ 키 추상화는 i18n 의 시작이다
```

**새 영문 노출 문구를 도입하지 않는다.** 화면에 보이는 글은 한국어로 통일한다.

## 정책이 바뀌면

다국어가 실제 요구사항이 되면 **이 문서를 먼저 갱신**하고 별도 작업으로 다룬다.
