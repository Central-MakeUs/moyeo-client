# Draggable Calendar 확정 요구사항 (spec-fixed)

> 단계 1(요구사항 인터뷰) 산출물. `spec-original.md`의 모호성·열린 질문을 확정한다.
> 이 문서가 확정("확정")되면 단계 2(PRD + ADR)로 진행한다.

## 1. 기능 개요

캘린더에서 **드래그(페인트)**와 **셀 탭(토글)**로 여러 날짜를 선택/해제하는 재사용 캘린더 인터랙션.
CRT-02(모임 생성 - 일정 정하기)의 조율 날짜 입력에 사용되며, 산출물은 모임 생성 payload의 `scheduleCandidateDates`가 된다.

컴포넌트는 `apps/web/src/shared/ui/primitives/calendar/`의 캘린더 primitive(`react-day-picker` 기반) 위에 구현한다.
3주 제한·비활성 규칙은 컴포넌트에 하드코딩하지 않고 **prop으로 주입**한다(`maxRangeDays`, `isDateDisabled` 등) → 다른 화면 재사용 가능.

## 2. 용어 정의 (Ubiquitous Language)

코드·문서·대화에서 아래 용어가 항상 같은 것을 가리킨다.

| 용어                    | 정의                                                                                          |
| ----------------------- | --------------------------------------------------------------------------------------------- |
| **셀(cell)**            | 캘린더의 날짜 한 칸. 활성/비활성 상태를 가진다.                                               |
| **선택(selected)**      | 사용자가 고른 날짜. 최종 산출물에 포함된다.                                                   |
| **페인트(paint)**       | 드래그 시작 셀 상태로 이번 드래그의 동작(모두 선택 or 모두 해제)이 하나로 고정되는 방식.      |
| **페인트 모드**         | `'select'`(모두 선택) 또는 `'deselect'`(모두 해제). 드래그 시작 시 결정되어 끝날 때까지 유지. |
| **드래그 범위**         | 시작 날짜와 현재 hover 날짜 **사이의 연속된 모든 날짜**(날짜 순서 기준, 그리드 사각형 아님).  |
| **비활성(disabled)**    | `isDateDisabled`가 true인 셀(예: 오늘 이전). 선택 대상에서 제외·드래그 중 건너뜀.             |
| **최대 기간(maxRange)** | 선택된 날짜의 min~max 스팬 상한. CRT-02에서는 3주(= 21일)를 주입.                             |
| **후보 날짜**           | 최종 선택 집합. `scheduleCandidateDates: string[]`(ISO `yyyy-MM-dd`)로 직렬화.                |

## 3. 확정된 요구사항

### 3-1. 날짜 선택/해제 (페인트)

- 드래그 시작 셀 상태에 따라 이번 드래그의 **페인트 모드가 하나로 고정**된다.
  - 시작 셀이 **미선택** → 드래그 대상 셀을 모두 **선택**(`select` 모드).
  - 시작 셀이 **선택** → 드래그 대상 셀을 모두 **해제**(`deselect` 모드).
  - 드래그 도중 셀마다 선택/해제가 뒤섞이지 않는다.
- 드래그 대상 = 시작 날짜와 현재 hover 날짜 사이의 **연속된 모든 날짜**(날짜 순서 기준).
  - 예: `6/9 → 6/18` 드래그 시 6/9~6/18 연속 10일 전부 대상.
- 각 셀은 드래그 외에 **단일 탭(토글)**로도 선택/해제 가능. (탭도 아래 3-2 제한을 따른다.)
- **비활성 셀은 선택 대상에서 제외**되며, 드래그 범위에 포함돼도 건너뛴다.
- 최종 선택은 **날짜들의 집합**이며(연속 기간이라는 의미는 없음), 저장 시 날짜 배열로 직렬화한다.

### 3-2. 선택 범위 제한 (3주)

- 선택 가능한 최대 스팬은 **3주 = 21일**이다. `maxRangeDays` prop으로 주입(CRT-02는 `21`).
- **경계 정의(기본 해석, GATE에서 확인):** 선택된 날짜의 `(max - min)` **일수 차가 20 이하**여야 한다.
  즉 min을 포함해 **연속 최대 21개 날짜 칸**까지 허용(예: 6/1을 min으로 두면 6/21까지 OK, 6/22부터 초과).
- **3주 초과 드래그 처리 — 시작점(anchor) 기준 자르기 (확정):**
  - **anchor** = 드래그 시작(pointerdown) 셀. **항상 보존**된다. (`min` 날짜 기준이 아님)
  - anchor에서 **드래그 방향으로** 3주(21칸) 이내 셀까지만 선택하고, anchor 반대편(움직이는 끝)에서 자른다.
  - 정방향 예: anchor 6/1 → 6/25까지 끌어도 `6/1~6/21`만 선택(6/22~6/25 잘림).
  - 역방향 예: anchor 6/25 → 6/1까지 끌면 `6/5~6/25`만 선택(6/1~6/4 잘림). anchor 6/25는 보존.
- **안내 표시 — 토스트 (확정):**
  - 3주 초과가 발생하면 **토스트로 "3주 내만 선택 가능"**을 안내한다.
  - 한 번의 드래그 제스처 동안 토스트는 **중복 노출하지 않는다**(제스처당 1회).

### 3-3. 월 이동 / 경계

- 캘린더는 한 번에 한 달을 표시하며, **선택 상태는 월 이동 후에도 유지**된다.
- 한 번의 드래그 제스처는 **현재 보이는 달 안에서만** 유효하다.
- **드래그 중 자동 월 넘김: MVP 제외 (확정).** 월 경계를 넘는 선택은 "월 이동 후 이어서 선택"으로 처리(백로그: 자동 월넘김).

### 3-4. 모바일 터치 — 드래그 vs 스크롤 (확정: 후보 A)

- 캘린더는 **한 달 고정 뷰**(내부 스크롤 없음)로 렌더한다.
- **드래그 활성 중 페이지 스크롤을 차단**한다(`touch-action: none` 등).
- 롱프레스 진입(후보 B)은 채택하지 않는다. (백로그)

### 3-5. 도메인 제약 (CRT-02에서 주입)

컴포넌트가 아니라 CRT-02 화면이 값으로 주입하는 규칙:

- 최대 선택 스팬: 3주(`maxRangeDays={21}`)
- 오늘 이전 날짜 비활성(`isDateDisabled` = 오늘/서버 시간 기준 이전 날짜)

## 4. 출력 (Output)

- `scheduleCandidateDates: string[]` — 선택된 날짜 배열, ISO `yyyy-MM-dd`, **오름차순 정렬**.
  - 예: `["2026-07-04", "2026-07-05"]`
  - 모임 생성 payload에 포함된다.
  - 시간대(`availableStartTime` / `availableEndTime`)는 별도 시간 피커(F03) 산출물이며 F01 범위 밖.

## 5. 인터뷰 결정 요약

| 열린 질문                    | 확정                                                          |
| ---------------------------- | ------------------------------------------------------------- |
| 모바일 터치 드래그 vs 스크롤 | **후보 A** — 한 달 고정 뷰 + `touch-action: none` 스크롤 차단 |
| 3주 초과 처리                | **시작점 기준 3주까지만 선택**                                |
| 초과 안내 표시               | **토스트** (제스처당 1회, 중복 노출 방지)                     |
| 드래그 중 자동 월 넘김       | **MVP 제외** (수동 월 이동, 백로그)                           |
| 3주 경계 셈법                | `max-min` 일수 차 ≤ 20 (연속 최대 21칸) — _GATE 확인 대상_    |

## 6. 남은 확인 사항 (비차단)

- 3주 경계 셈법(위 5의 마지막 행)이 PM 의도와 일치하는지 최종 확인. (기본 해석으로 진행 가능)
- 토스트 컴포넌트/패턴 존재 여부는 단계 2에서 코드베이스 확인.
