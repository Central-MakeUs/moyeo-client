# 모임 홈 화면 확정 요구사항 (spec-fixed)

> 단계 1(요구사항 인터뷰) 산출물. `spec-original.md`의 모호성·열린 질문을 확정한다.
> 이 문서가 확정("확정")되면 단계 2(PRD + ADR)로 진행한다.

## 1. 기능 개요

로그인한 회원이 앱 진입 시 보는 **모임 홈 화면**. "진행 중 모임" 캐러셀과 "확정된 모임" 리스트를 함께 보여준다.

**범위는 PM이 전달한 최종 mockup 화면 자체다.** `spec-original.md`의 명세표(HOME-01-F01~F08)는 배경 참고 자료이며,
F04(확정된 모임 모달)·F05(공유 버튼)는 이번 범위에서 제외한다(§4 Out of Scope).

**FAB은 이번 범위에서 완전히 제외한다.** 다른 브랜치에서 이미 작업 중이며, 병합 시 화면에 자연히 반영된다.
이번 이슈들은 FAB 컴포넌트를 만들거나 자리(placeholder)를 잡지 않는다.

**프로필 아이콘 → 마이페이지 라우팅은 이번 범위에 반드시 포함한다**(§3.7). 목적지 화면(마이페이지) 자체 구현은
별도 이슈이지만, 상단바 프로필 버튼 탭 시 실제 경로로 이동하는 동작은 이 이슈들에서 완료해야 한다.

## 2. 용어 정의 (Ubiquitous Language)

| 용어                               | 정의                                                                                                            |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| **진행 중 모임**                   | 아직 일정/장소가 확정되지 않아 참여자들이 조율 중인 모임.                                                       |
| **확정된 모임**                    | 일시(또는 장소)가 확정된 모임.                                                                                  |
| **정원(capacity)**                 | 모임에 참여 가능한 최대 인원 수.                                                                                |
| **참여자 수(joinedCount)**         | 실제로 참여를 완료한 인원 수. `joinedCount ≤ capacity`.                                                         |
| **진행 카드(card-meeting)**        | 진행 중 모임 캐러셀의 슬라이드 한 장. 제목, 마감 배지, 커버 이미지, avatar-group, "N/N명 참여중" 텍스트로 구성. |
| **확정 카드(confirmed-list-item)** | 확정된 모임 리스트의 한 행. 제목, 확정 일시, 확정 장소, 커버 썸네일로 구성. 탭 핸들러 없음(§3.7).               |
| **avatar-group**                   | 참여 현황을 아바타 아이콘으로 시각화하는 공용 컴포넌트. 정원·참여자 수 기반 표시 규칙은 §3.4.                   |
| **마감 배지**                      | 진행 카드에 표시되는, 모임 마감까지 남은 시간 배지. 포맷 규칙은 §3.5.                                           |
| **페이지 컨트롤(page-control)**    | 캐러셀 하단의 점(dot) 인디케이터. 활성 페이지 = 빨간 알약, 비활성 = 회색 점.                                    |
| **FAB(Floating Action Button)**    | 화면 우하단에 고정된 원형 버튼. 탭 시 모임 생성 플로우로 이동.                                                  |

## 3. 확정된 요구사항

### 3-1. 레이아웃 구성

화면은 위에서부터 순서대로 아래 4개 영역으로 구성된다.

1. 상단바 — MOYEO 로고(`shared/assets/illustrations/moyeo-logo.svg`, 이미 존재) + 우측 프로필 아이콘 버튼.
2. "진행 중 모임 N" 섹션 — 섹션 타이틀(N = 진행 중 모임 개수) + 진행 카드 캐러셀 + 페이지 컨트롤.
3. "확정된 모임 N" 섹션 — 섹션 타이틀(N = 확정된 모임 개수) + 확정 카드 리스트(세로 나열).

두 섹션은 각각 독립적으로 존재하며, 한쪽이 비어도 다른 쪽은 그대로 표시된다(§3.6).
FAB은 이번 범위에서 다루지 않는다(별도 브랜치, 위 "기능 개요" 참고).

### 3-2. 진행 중 모임 캐러셀

- 한 번에 **카드 1개만** 표시하고, **스와이프(터치 드래그)**로 다음/이전 카드로 전환한다.
- 하단에 페이지 컨트롤(dot)을 표시한다. 카드 개수만큼 점이 생기고, 활성 페이지만 빨간 알약 모양으로 강조한다.
- 진행 카드 내부 구성: 제목, 마감 배지(§3.5), 커버 이미지(§3.6), avatar-group(§3.4) + "`joinedCount`/`capacity`명 참여중" 텍스트.
- 카드 탭 시 모임 현황(VIEW-01) 경로 `/meetings/[meetingId]`로 **해당 모임의 실제 `meetingId`를 포함해** 라우팅한다(§3.7).
  목적지 화면의 실제 구현은 범위 밖이나, **placeholder 페이지에 `meetingId` 값을 표시**해 카드마다 다른 모임으로
  정확히 이동하는지 확인할 수 있게 한다(§3.7).

### 3-3. 확정된 모임 리스트

- 확정 카드를 세로로 나열한다(캐러셀 아님, 페이징 없음).
- 카드 내부 구성: 제목, 확정 일시(예: "2026년 7월 18일 14시"), 확정 장소(있을 경우만 표시), 우측 커버 썸네일.
- **카드에는 탭 핸들러를 두지 않는다**(모달·상세 이동 없음, §4 Out of Scope).

### 3-4. avatar-group 표시 규칙 (핵심 로직)

입력: `capacity`(정원), `joinedCount`(참여자 수). `unfilledCount = capacity - joinedCount`.

- **정원 ≤ 5명:** `capacity`개의 아바타 원을 전부 표시한다. 표시 순서는 **회색(미참여/빈자리) 먼저, 그다음 빨간색(참여)** 이다.
  - 예: `capacity=5, joinedCount=3` → 회색 2개 + 빨간색 3개 (`⚪⚪🔴🔴🔴`).
- **정원 > 5명:** 아바타 원은 **4개만** 표시하고, 5번째 자리에 오버플로 배지 `"+N"`(빨간색)을 표시한다.
  - `N = capacity - 4` (표시되지 않는 나머지 전부. 참여 여부와 무관하게 고정값).
  - 4개 슬롯의 회색/빨간색 구성은 `grayShown = min(4, unfilledCount)`, `redShown = 4 - grayShown` 이며, **회색이 항상 먼저** 온다.
  - 예1: `capacity=20, joinedCount=13` → `unfilledCount=7` → `grayShown=min(4,7)=4`, `redShown=0` → `⚪⚪⚪⚪ +16`.
  - 예2: `capacity=20, joinedCount=18` → `unfilledCount=2` → `grayShown=2`, `redShown=2` → `⚪⚪🔴🔴 +16`.
- 이 컴포넌트는 진행 카드뿐 아니라 다른 화면(예: 일정 조율의 "N/N명 가능")에서도 재사용될 수 있도록 `capacity`/`joinedCount`를 prop으로 주입받는 범용 컴포넌트로 만든다(shared/ui).

### 3-5. 마감 배지 포맷 규칙

마감 시각까지 남은 시간(`deadline - now`)에 따라 아래 3구간으로 텍스트가 바뀐다.

| 남은 시간              | 표시 텍스트 예시                                             |
| ---------------------- | ------------------------------------------------------------ |
| 24시간 이상 남음       | `마감 D-N` (N = 남은 일수, 올림 또는 내림은 단계 2에서 확정) |
| 1시간 이상 24시간 미만 | `마감 N시간 전`                                              |
| 1시간 미만             | `마감 0시간 전`                                              |

- 계산 시점은 **컴포넌트 마운트 / 데이터 리패치 시점**뿐이다. 화면에 머무는 동안 실시간(interval)으로 재계산하지 않는다.

### 3-6. Empty State

- **진행 중 모임 섹션**이 비어 있으면(0개), 해당 섹션 자리에 안내 문구(F07 "아직 모임이 없어요" 계열)를 표시한다. 캐러셀·페이지 컨트롤은 렌더링하지 않는다.
- **확정된 모임 섹션**도 동일하게, 비어 있으면 섹션별 안내 문구를 표시한다.
- 두 섹션은 **독립적으로** 판단한다 — 한쪽만 비어도 다른 쪽은 정상 표시된다.
- 커버 이미지가 없는 모임(진행 카드/확정 카드 공통)은 기본 플레이스홀더(로고 또는 단색 배경)로 대체한다.

### 3-7. 네비게이션

이번 이슈는 **라우팅 연결까지만** 한다. 목적지 화면 자체의 실제 구현은 범위 밖(다른 이슈)이며, 현재 대부분 placeholder 상태다.

| 트리거           | 목적지                                                                        |
| ---------------- | ----------------------------------------------------------------------------- |
| 진행 카드 탭     | `/meetings/{meetingId}` (모임 현황, VIEW-01) — 카드별 실제 `meetingId`로 이동 |
| 확정 카드 탭     | **없음** — 탭 핸들러를 두지 않는다.                                           |
| 프로필 아이콘 탭 | **마이페이지(HOME-01-A) 경로로 이동 — 이번 범위에 반드시 포함**               |

FAB 탭 동작(모임 생성 이동)은 FAB 자체가 이번 범위 밖이므로 다루지 않는다.

**검증용 placeholder 표시(이번 범위 포함):** `apps/web/app/meetings/[meetingId]/page.tsx`(기존 "VIEW-01 placeholder" 텍스트만 있는 페이지)에
route param `meetingId` 값을 화면에 표시하도록 최소 수정한다. 홈 화면에서 서로 다른 진행 카드를 탭했을 때 실제로 다른
`meetingId`로 이동하는지 눈으로 확인하기 위함이며, VIEW-01 화면의 실제 기능 구현은 아니다(§4 Out of Scope 유지).

### 3-8. 데이터 로딩 / 에러 처리

- 모임 목록·참여자 정보는 TanStack Query(Orval 생성 훅) 기반으로 조회한다.
- **로딩 중**: 화면에 텍스트로 "로딩중" 표시(스켈레톤 등 정교한 처리는 이번 범위 밖, 후속 이슈).
- **에러 발생 시**: 화면에 텍스트로 에러 메시지만 표시(재시도 버튼 등은 후속 이슈).

### 3-9. 기술/구조 결정 (요약, 상세는 PRD 단계에서 ADR로)

- **API**: 백엔드에 모임 목록 조회 엔드포인트가 이미 존재. openapi 스펙 재생성 + Orval codegen 갱신이 선행 작업으로 필요.
- **FSD 위치**: 모임 도메인 타입/목록 조회 훅/마감시간 계산 등 도메인 로직은 신설하는 `entities/meeting`에 둔다(레포 최초의 entities 슬라이스). 기존 `features/meeting/create-meeting`(모임 생성 액션)과는 레이어가 다르다. 순수 UI 컴포넌트(카드/아바타/캐러셀/FAB)는 `shared/ui`에, 화면 조립은 `widgets`/`_pages/home`에 둔다.
- **재사용**: 상단바는 기존 `shared/ui/top-app-bar`(leading/title/trailing 슬롯)를 재사용한다.
- **FAB**: 이번 범위에서 제외(다른 브랜치에서 진행 중, §1 참고).
- **신규 shadcn/공용 컴포넌트**: Avatar, AvatarGroup, Carousel(또는 자체 스와이프 구현), PageControl(dot), CardMeeting, ConfirmedListItem.

## 4. Out of Scope

- **F04 확정된 모임 모달**, **F05 공유 버튼** — 이번 이슈에서 만들지 않는다.
- **FAB(모임 생성 버튼)** — 다른 브랜치에서 이미 작업 중. 컴포넌트도, 자리(placeholder)도 만들지 않는다. 병합 시 자연히 반영.
- 진행 카드/프로필 버튼이 이동하는 **목적지 화면의 실제 구현**(VIEW-01 모임 현황, HOME-01-A 마이페이지) — 라우팅 연결만 하고 화면 구현은 각각 별도 이슈. (단, 라우팅 연결 자체와 VIEW-01 placeholder에 `meetingId` 확인용 표시를 추가하는 것은 이번 범위에 포함, §3.7.)
- 확정 카드 탭 인터랙션 전반(모달이든 상세 페이지든) — 탭 핸들러 자체를 두지 않는다.
- 마감 시간 **실시간(interval) 갱신** — 마운트/리패치 시점 계산만.
- 로딩/에러의 정교한 UX(스켈레톤, 재시도 버튼, 토스트 등) — 텍스트 표시만.
- 참여자 아바타에 프로필 이미지 자체를 실제로 렌더링하는 것(이미지 유무에 따른 처리) — 이번엔 회색/빨간색 아이콘 표현까지만, 실제 프로필 사진 표시 여부는 API 응답 필드 확인 후 후속 이슈에서 다룰 수 있음.

## 6. 남은 확인 사항 (비차단, 단계 2에서 코드베이스/API 확인)

- 실제 openapi 스펙 재생성 후, 모임 목록 응답에 `capacity`/`joinedCount`/`deadline`/`coverImageUrl`/확정 일시·장소 필드가 그대로 존재하는지 확인 필요.
- 마감 배지의 "N일" 계산 시 올림/버림/반올림 여부는 PRD 단계에서 코드 구현 시 확정.
- `entities/meeting`과 기존 `features/meeting/create-meeting`(모임 생성) 사이의 타입 재사용/중복 여부는 PRD 단계에서 정리.
