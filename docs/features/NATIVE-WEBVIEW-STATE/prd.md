# Native WebView 연결 상태 처리 — PRD

## 개요

네이티브 앱의 WebView가 로딩 중이거나 네트워크 단절·문서 로드 실패 상태일 때 빈 화면 대신
명확한 안내와 복구 수단을 제공한다.

## 사용자 가치

- 앱이 멈춘 것처럼 보이는 최초 로딩 구간을 줄인다.
- 인터넷 연결이 끊겼는지 문서 로드가 실패했는지 사용자가 이해할 수 있다.
- 일시적인 로드 실패 후 앱을 종료하지 않고 다시 시도할 수 있다.

## 범위

- WebView 최초 로딩 상태 표시
- 네트워크 연결·인터넷 도달 가능성 감지
- WebView `onLoad`·`onError` 기반 상태 전환
- 실패 후 수동 `reload()`
- iOS·Android 공통 네이티브 UI

## 사용자 스토리

- 사용자는 앱을 연 직후 웹 화면이 준비 중임을 알 수 있다.
- 사용자는 네트워크가 끊기면 원인과 다음 행동을 알 수 있다.
- 사용자는 일시적인 로드 실패 후 버튼을 눌러 다시 불러올 수 있다.

## 기존 기반

- 화면 조립: `apps/native/app/index.tsx`의 `HomeScreen`
- 네트워크 감지: `@react-native-community/netinfo`가 `main`에 이미 설치됨
- 문서 상태: `react-native-webview`의 `onLoad`, `onError`, `reload()`
- 자동 테스트: `apps/native`에는 테스트 러너가 없으며 `lint`, `check-types`만 연결됨
- 복원 원본: `stash@{2}`에 인라인 상태·오버레이 구현이 남아 있음
- 오류 화면 디자인: 구현 전 Figma MCP로 대상 프레임을 조회하고 네이티브 UI에 맞게 적용

## 기술 대안

### A. `HomeScreen` 안에 상태와 오버레이를 인라인으로 복원

- `isOffline`, `webViewLoadState`를 `HomeScreen` 로컬 상태로 관리한다.
- NetInfo 구독, 재시도 함수, 오버레이 JSX와 스타일을 `index.tsx`에 둔다.
- stash 구현을 관련 hunk 단위로 복원할 수 있어 변경량과 구현 위험이 가장 작다.
- 단점은 이미 큰 `index.tsx`의 책임과 길이가 더 늘어난다는 점이다.

### B. 연결 상태 훅과 오버레이 컴포넌트로 분리

- 네트워크·WebView 상태 전이를 전용 훅으로 분리한다.
- 표시 UI를 별도 네이티브 컴포넌트로 분리한다.
- 상태 전이와 화면 책임이 명확하고 향후 자동 테스트를 붙이기 쉽다.
- 현재 한 화면에서만 쓰는 기능에 파일과 추상화가 늘고, stash를 그대로 활용할 수 없다.

### C. NetInfo 없이 WebView 이벤트만 사용

- `onLoad`, `onError`만으로 로딩과 실패를 구분한다.
- 의존 상태와 분기가 가장 단순하다.
- 오프라인과 서버·문서 오류를 구분하지 못하고, 오프라인 상태에서 재시도 버튼을 막을 수 없어
  확정 명세를 충족하지 않는다.

## 추천안

**A. `HomeScreen` 인라인 복원**을 추천한다.

현재 기능은 네이티브 셸의 단일 WebView에만 적용되고 stash에 검토 가능한 구현이 이미 있다.
이번 이슈에서는 관련 hunk만 선택 복원해 사용자 복구 흐름을 완성하고, 연결 상태가 다른 화면에서도
필요해질 때 훅·컴포넌트 추출을 별도 리팩터링으로 다루는 편이 변경 위험이 작다.

## 기술 결정

### `HomeScreen` 인라인 연결 상태 관리

**Context** — 연결 상태 UI는 현재 네이티브 셸의 단일 WebView에서만 필요하고,
`stash@{2}`에 NetInfo 구독·WebView 이벤트·오버레이를 한곳에서 관리하는 구현이 남아 있다.
`apps/native`에는 자동 테스트 러너가 없어 이번 이슈에서 새 추상화의 독립 테스트 이점도 얻기 어렵다.

**Decision** — `apps/native/app/index.tsx`의 `HomeScreen`에서 `isOffline`과
`webViewLoadState`를 로컬 상태로 관리한다. NetInfo 구독, WebView `onLoad`·`onError`, 수동
`reload()`와 상태별 오버레이를 같은 화면 책임 안에 둔다. stash 파일 전체가 아니라 연결 상태와
관련된 hunk만 복원한다. 오류·오프라인 오버레이의 시각 요소는 stash 스타일을 최종안으로 보지 않고,
Figma 대상 노드의 디자인 컨텍스트를 기준으로 구현한다.

**Alternatives** — 전용 훅과 오버레이 컴포넌트 분리는 단일 사용처에 불필요한 파일과 추상화를
늘려 제외했다. WebView 이벤트만 사용하는 방식은 오프라인과 일반 로드 실패를 구분하지 못해
확정 명세를 충족하지 않으므로 제외했다.

**Consequences** — 기존 구현을 활용해 변경량과 회귀 위험을 줄이고 상태 전이를 한 화면에서
추적할 수 있다. 반면 이미 큰 `index.tsx`가 더 길어진다. 동일한 연결 상태 UI가 다른 화면에도
필요해지거나 네이티브 테스트 러너가 도입되면 훅·컴포넌트 분리를 다시 검토한다.

## Out of Scope

- 웹 애플리케이션 내부 API·SDK·이미지 오류 처리
- 네트워크 복구 즉시 자동 재로드
- 오프라인 데이터 캐시
- 연결 상태 UI의 공용 컴포넌트화
- 네이티브 테스트 러너 도입

## 용어 정의

용어와 상태 우선순위는 `spec-fixed.md`를 따른다.
