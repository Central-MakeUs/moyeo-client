# Native WebView 연결 상태 처리 — 확정 명세

## 개요

Expo 네이티브 셸이 서비스 WebView를 불러오는 동안 사용자에게 현재 상태를 알리고,
네트워크 단절 또는 문서 로드 실패 시 빈 화면 대신 복구 가능한 안내를 제공한다.

## 용어

- **로딩**: WebView가 문서 로드를 시작했지만 `onLoad`가 아직 호출되지 않은 상태.
- **오프라인**: 네트워크 연결 또는 인터넷 도달 가능성이 명시적으로 `false`인 상태.
- **판정 대기**: WebView의 `onError` 이후 네트워크 상태가 확정되기를 제한 시간 동안 기다리는 상태.
- **로드 실패**: 온라인으로 판정된 상태에서 WebView의 `onError`가 호출된 상태.
- **연결 상태 오버레이**: WebView 위를 덮어 로딩 또는 실패 안내를 표시하는 네이티브 UI.

## 사용자 시나리오

### 1. 최초 로딩

- 앱이 WebView 문서 로드를 시작하면 연결 상태 오버레이를 표시한다.
- 오버레이에는 진행 표시만 두고 문구는 표시하지 않는다.
- WebView의 `onLoad`가 호출되면 오버레이를 제거하고 웹 화면을 노출한다.

### 2. 네트워크 단절

- 네트워크 연결 또는 인터넷 도달 가능성이 명시적으로 끊기면 WebView 위에 오프라인 안내를 표시한다.
- 안내는 오류 아이콘과 제목 `네트워크 연결이 끊겼어요`로 구성한다.
- 오프라인인 동안 재시도 버튼은 비활성이고 `연결을 기다리는 중`을 표시한다.
- 네트워크 상태가 아직 판정되지 않은 `null`은 오프라인으로 취급하지 않는다.
- 연결이 돌아오면 끊기기 전의 로드 상태로 판단한다.
  - 끊기기 전에 문서가 이미 떠 있었으면 오버레이만 걷고 화면을 그대로 둔다. 자동으로 다시 불러오지 않는다.
  - 끊기기 전에 아직 뜨지 않았으면 로드 실패 안내를 표시하고 사용자가 직접 재시도하게 한다.

### 3. WebView 로드 실패와 재시도

- WebView의 `onError`가 호출되면 최대 1.5초 동안 판정 대기 상태를 유지한다.
- 판정 대기 중에는 문구 없이 진행 표시만 둔다. 대기 중에 오프라인이 확정되면 즉시 시나리오 2로 넘어간다.
- 제한 시간 안에 오프라인이 확정되지 않으면 로드 실패 안내를 표시한다.
- 판정 대기 중에 WebView 로드가 성공하거나 사용자가 재시도하면 이전 판정 결과를 폐기한다.
- 안내는 오류 아이콘과 제목 `결과를 불러오지 못했어요`로 구성한다.
- 사용자가 `다시 시도하기`를 누르면 로딩 상태로 전환하고 WebView의 `reload()`를 호출한다.
- 재시도한 문서의 `onLoad`가 호출되면 오버레이를 제거한다.

### 4. WebView 프로세스 종료 복구

- 앱이 오래 백그라운드에 머무는 등의 이유로 OS가 WebView 프로세스를 종료하면 로딩 상태로 전환하고 진행 중이던 오류 판정을 폐기한다.
- 백그라운드에서 전달된 일시적인 네트워크 단절 값은 화면에 반영하지 않고, 앱이 다시 활성화될 때 연결 상태를 갱신한다.
- 프로세스 종료나 로드 오류가 백그라운드에서 발생하면 실제 복구는 보류하고, 앱이 다시 활성화된 뒤 실행한다.
- iOS는 기존 WebView를 다시 불러온다. WebView 자체는 살아 있으므로 방문 기록이 유지된다.
- Android는 종료된 렌더러를 쓸 수 없으므로 WebView 인스턴스를 새로 만들고, 종료 직전에 보고 있던 주소를 다시 불러온다. 새 인스턴스에는 방문 기록이 없다.
- 앱이 포그라운드로 돌아왔다는 이유만으로 정상 WebView를 일괄 재로드하지 않는다.

## 상태 우선순위

1. 오프라인이면 WebView 로드 상태와 관계없이 오프라인 안내를 표시한다.
2. 온라인이고 로딩 중이거나 판정 대기 중이면 진행 표시만 표시한다.
3. 온라인이고 로드에 실패했으면 실패 안내와 재시도를 표시한다.
4. 온라인이고 로드가 완료됐으면 오버레이를 표시하지 않는다.

## 범위

- `apps/native`의 WebView 연결·로드 상태 감지
- 로딩, 오프라인, 로드 실패 오버레이
- 실패 후 WebView 재로드
- OS에 의해 종료된 WebView 프로세스 복구
- iOS와 Android에서 동일한 사용자 흐름

## 범위 제외

- 웹 애플리케이션 내부 API 오류 처리
- 카카오 지도 SDK처럼 WebView 문서 로드 이후 발생하는 개별 웹 리소스 오류 처리
- 네트워크가 복구되는 즉시 자동으로 WebView를 재로드하는 동작
- 반복되는 WebView 프로세스 종료에 대한 재생성 횟수 제한
- 오프라인 콘텐츠 캐시 또는 오프라인 모드
- 디자인 시스템 공용 컴포넌트 추출

## 검증 기준

- 오류·오프라인 화면의 레이아웃, 이미지, 색상, 타이포그래피는 대상 Figma 프레임을 시각적 기준으로 삼는다.
- 구현 전 Figma MCP의 `get_design_context`로 대상 노드의 디자인 컨텍스트를 확인한다.
- `apps/native`에는 자동 테스트 러너가 없으므로 정적 검증은 lint와 typecheck를 사용한다.
- 사용자 동작은 iOS와 Android 실기기 또는 개발 빌드에서 수동으로 검증한다.
- 네트워크 단절, 온라인 복구, 서버 접근 실패, 재시도 성공을 각각 확인한다.
