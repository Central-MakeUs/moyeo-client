## 4. 라우트 및 화면 이동

| 사용자 동작                                        | 이동 또는 처리                                                              |
| -------------------------------------------------- | --------------------------------------------------------------------------- |
| 모임장 정보 입력(INV) 및 `POST /api/meetings` 성공 | `/meetings/[meetingId]/invite`로 이동                                       |
| SMS 선택                                           | SMS 공유 기능을 실행하고 현재 화면 유지                                     |
| 카카오톡 선택                                      | 카카오톡 공유 기능을 실행하고 현재 화면 유지                                |
| URL 복사 선택                                      | 링크를 복사하고 현재 화면에 성공 토스트 표시                                |
| 하단 버튼 선택                                     | 버튼 문구와 이동 목적지 확인 필요                                           |
| 상단 뒤로가기 선택                                 | 생성이 완료된 CRT·INV 입력 화면으로 돌아가지 않으며 이동 목적지는 확인 필요 |

CRT-07의 확정 경로는 `/meetings/[meetingId]/invite`이다. 모임장 정보 입력까지 마치고 모임 생성
요청이 성공한 경우에만 진입한다.

## 5. 화면 입력 데이터

이 화면에서 사용자가 새로 입력하거나 선택하여 서버에 저장하는 값은 없다.

| 화면 표시 값   | 생성 응답 필드 | 필수 여부   | 제약             | 값이 없을 때                                    |
| -------------- | -------------- | ----------- | ---------------- | ----------------------------------------------- |
| 모임 식별자    | `meetingId`    | 응답상 선택 | 숫자             | CRT-07 경로를 구성할 수 없으므로 예외 처리 필요 |
| 초대 링크 경로 | `invitePath`   | 응답상 선택 | 상대 경로 문자열 | `inviteCode`를 이용한 조립 가능 여부 확인       |
| 초대 코드      | `inviteCode`   | 응답상 선택 | 문자열           | `invitePath`도 없다면 링크 표시·공유 불가       |

생성 응답은 완성된 절대 URL이 아니라 `invitePath`와 `inviteCode`를 제공한다. 화면에 표시할 절대
URL의 도메인과 조립 규칙은 별도로 확정해야 한다.

## 7. 기능별 동작

### CRT-07-F01 생성 완료 안내

- 모임장 정보 입력과 서버의 모임 생성 요청이 모두 성공한 뒤 노출한다.
- 제목은 `초대장을 만들었어요!`로 표시한다.
- 안내 문구는 `함께하고 싶은 친구들에게 초대장을 보내주세요`로 표시한다.

### CRT-07-F02 초대 링크 표시

- 생성 응답의 `invitePath` 또는 `inviteCode`를 기반으로 공유 링크를 구성한다.
- 구성된 링크를 링크 아이콘과 함께 한 줄로 표시한다.
- 링크가 준비되지 않은 경우 잘못된 URL을 표시하거나 공유 기능을 활성화하지 않는다.

### CRT-07-F03 SMS 공유

- SMS 버튼을 누르면 구성된 초대 링크를 SMS로 공유할 수 있는 기능을 실행한다.
- 공유를 취소하거나 완료한 뒤에는 CRT-07을 유지한다.

### CRT-07-F04 카카오톡 공유

- 카카오톡 버튼을 누르면 구성된 초대 링크를 카카오톡으로 공유할 수 있는 기능을 실행한다.
- 공유를 취소하거나 완료한 뒤에는 CRT-07을 유지한다.

### CRT-07-F05 URL 복사

- URL 복사 버튼을 누르면 구성된 초대 링크를 클립보드에 복사한다.
- 복사에 성공하면 `링크가 복사되었어요` 토스트를 표시한다.
- 복사 실패 시 처리는 확인이 필요하다.

### CRT-07-F06 하단 버튼

- Figma에는 `내 정보 입력하기` 버튼이 표시되어 있다.
- CRT-07 진입 전에 모임장 정보 입력이 이미 끝난다는 확정 흐름과 버튼 문구가 충돌한다.
- 확정된 문구와 이동 목적지가 정해지기 전까지 임의로 동작을 지정하지 않는다.

### CRT-07-F07 뒤로가기

- 모임과 모임장 정보가 이미 서버에 제출된 완료 화면이다.
- 뒤로가기로 완료된 CRT 또는 INV 입력 플로우를 다시 열지 않는다.
- 최종 이동 목적지는 기획 확인 후 기록한다.

## 8. 검증 기준

- [ ] 모임장 정보 입력과 모임 생성 요청이 성공한 경우에만 CRT-07이 열린다.
- [ ] 실제 경로가 `/meetings/[meetingId]/invite`이다.
- [ ] 제목과 안내 문구가 Figma와 일치한다.
- [ ] 생성 응답을 기반으로 초대 링크가 표시된다.
- [ ] SMS, 카카오톡, URL 복사 버튼이 Figma의 순서대로 표시된다.
- [ ] URL 복사 성공 시 `링크가 복사되었어요` 토스트가 표시된다.
- [ ] 공유를 취소하거나 완료한 뒤 CRT-07 화면을 유지한다.
- [ ] 뒤로가기로 완료된 CRT·INV 입력 플로우가 다시 열리지 않는다.
- [ ] 하단 버튼은 확정된 문구와 이동 정책을 따른다.

## 9. 확인 필요

1. CRT-07 진입 전에 모임장 정보 입력이 완료되므로, Figma의 `내 정보 입력하기` 버튼 문구와 실제
   이동 목적지를 변경해야 한다.
2. 상단 뒤로가기 버튼이 이동할 최종 화면을 정해야 한다. 완료된 CRT·INV 입력 플로우로는 돌아가지
   않는다.
3. `invitePath` 또는 `inviteCode`로 사용자에게 표시할 절대 URL을 구성하는 규칙을 정해야 한다.
4. SMS와 카카오톡 공유에 사용할 플랫폼별 공유 방식을 정해야 한다.
5. URL 복사 실패 시 사용자에게 보여줄 피드백을 정해야 한다.
