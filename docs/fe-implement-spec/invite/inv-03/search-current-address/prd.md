## 1. 개요

### 무엇을

출발지 검색 화면(INV-03-A)의 `현재 위치로 찾기` 버튼을 누르면, 기기의 현재 좌표를 지도에
띄우고 사용자가 핀 위치를 확인·조정한 뒤 출발지로 확정하는 화면(INV-03-B)을 제공한다.

### 왜

출발지 입력은 INV-03의 **필수값**이고, 지금은 텍스트 검색이 유일한 경로다. 자기가 지금 있는
곳의 주소를 모르거나 검색어로 옮기기 어려운 사용자는 여기서 막힌다. 모임 생성·참여 흐름의
마지막 단계라 여기서 막히면 전환이 통째로 끊긴다.

시안(`INV-03-6`)에 버튼이 이미 그려져 있고 `DepartureQuickSelect`에 렌더돼 있으나 아직
동작하지 않는다. 누르면 아무 일도 일어나지 않는 버튼이 화면에 남아 있는 상태다.

### 성공 기준

- 사용자가 검색어를 한 글자도 입력하지 않고 출발지를 확정할 수 있다.
- 권한 거부·위치 실패·지원 지역 밖에서 **막다른 길이 생기지 않는다** — 모든 실패 상태에서
  검색 화면으로 돌아갈 수 있다.
- 뒤로가기 4경로(Android 하드웨어 / iOS 스와이프 / 브라우저 / 화면 내 버튼)가 같은 결과를 낸다.

## 2. 가정과 전제

Stage 1에서 결론이 나지 않은 항목이다. **아래 가정 위에서 설계를 진행하며**, 가정이
무너지면 명시한 범위만 영향을 받도록 설계를 격리한다.

### A1. 위치정보법상 별도 동의 UI가 필요하지 않다

- **가정 근거**: 포그라운드 1회 좌표만 확인하고, 확정 전 좌표는 저장하지 않으며,
  사용자가 CTA로 확정한 출발지만 기존 `departure` 필드로 서버에 저장한다.
  지속 추적·이력 보관·제3자 공유가 없다.
- **무너지면**: 진입 시점(F01과 F02 사이)에 동의 화면 한 단계와 동의 상태 저장소가 추가된다.
  **지도·좌표·주소 설계는 바뀌지 않는다.** 이슈 하나가 앞에 붙는 형태다.
- **격리 방법**: 좌표 요청을 F02 한 곳(`useCurrentLocation` 진입점)에서만 시작하도록 묶어,
  동의 게이트가 필요해지면 그 앞에 한 번만 끼우면 되게 한다.
- **확인 기한**: 2차(앱) 스토어 제출 전. **1차 웹 릴리스는 이 가정으로 진행한다.**

### A2. 카카오 지도 Web SDK가 WebView에서 정상 동작한다

- **가정 근거**: 카카오 공식 문서가 모바일 웹을 지원 대상으로 명시한다. WebView도 같은
  서비스 웹 URL을 띄운다.
- **무너지면 (팬·줌 불가)**: 지도 상호작용을 포기하고 "현재 위치의 주소를 확인하고 확정만"
  하는 축소 화면이 된다. F03·F04·F06이 사라지고 F09(지원 지역 밖)는 재조정 수단이 없어져
  진입 즉시 차단으로 바뀐다. **기능 명세의 절반이 영향받는다.**
- **무너지면 (렌더링 자체 불가)**: 웹 브라우저 전용 기능으로 축소하거나 Expo Maps 네이티브
  화면으로 전환해야 한다. 후자는 웹을 지원하지 않으므로 §11의 "웹 1차" 릴리스 전략이 성립하지
  않는다. **릴리스 계획 재수립 대상이다.**
- **확인 기한**: **이슈 분해 전** (스파이크 S1). 1차 릴리스는 웹 브라우저라 스파이크 없이도
  시작할 수 있으나, 앱에서 못 쓰는 것이 확정되면 만들 물건이 달라진다.

### A3. 쿼리만 바뀌는 내비게이션에서 인터셉팅 슬롯이 유지된다

- **가정 근거**: 라우트 세그먼트가 바뀌지 않으므로 `@modal/(.)search`의 매칭이 유지될 것으로
  본다. Next 16에서 실측하지 않았다.
- **무너지면**: 모임장 위저드(`/meetings/new/departure/search`) **한 곳만** 영향받는다.
  해당 진입점에 한해 별도 route로 예외 처리한다. 다른 세 진입점은 독립 페이지라 무관하다.
- **확인 기한**: 스파이크 S1과 함께.

### A4. 기존 뒤로가기 브리지를 수정하지 않는다

- `BACK_PRESSED`/`BACK_RESULT`·`runBackHandlers`·`NativeBackProvider`·네이티브 `BackHandler`는
  이미 동작하며, 이 기능은 **핸들러를 하나 더 등록할 뿐** 브리지 자체를 건드리지 않는다.
- 새로 추가하는 브리지 메시지는 `GET_CURRENT_LOCATION` / `CURRENT_LOCATION_RESULT` 둘뿐이고,
  2차(앱) 릴리스 범위다.

## 3. 사용자 스토리

### US-1. 지금 있는 곳을 그대로 출발지로 쓴다 (해피 패스)

> 카페에서 친구들과 모임을 잡는 중이다. 이 카페 주소를 모른다.
> `현재 위치로 찾기`를 누르니 권한을 묻고, 허용하자 지도에 지금 있는 곳이 뜬다.
> 하단에 도로명 주소가 보인다. 맞다. `이 위치로 설정`을 누르니 출발지 입력 화면으로
> 돌아가 있고 주소가 채워져 있다. 이동수단만 고르고 다음으로 넘어간다.

### US-2. 지도를 옮겨 조정한다

> GPS가 옆 건물을 가리킨다. 지도를 손가락으로 끌어 내가 있는 건물로 옮긴다.
> 끄는 동안 하단 주소가 로딩으로 바뀌고 확정 버튼이 눌리지 않는다.
> 손을 떼자 새 주소가 뜬다. 이제 맞다. 확정한다.

### US-3. 권한을 거부했다가 마음을 바꾼다

> 위치 권한 팝업에서 실수로 거부를 눌렀다. 왜 위치가 필요한지 설명이 뜨고
> `다시 시도` 버튼이 있다. 눌러서 이번엔 허용한다.
> (거부한 채로 두면 `검색으로 돌아가기`로 원래 검색 화면에 돌아가 직접 검색한다.)

### US-4. 뒤로가기로 취소한다

> 지도를 보다가 그냥 검색으로 찾기로 마음을 바꿨다.
> 뒤로가기를 누르니 검색 화면으로 돌아왔고, 출발지는 아무것도 선택되지 않은 그대로다.
> (안드로이드 하드웨어 버튼, 아이폰 화면 끝 스와이프, 화면 안 뒤로가기 버튼 모두 같다.)

### US-5. 지원 지역 밖에 있다

> 부산 출장 중인데 다음 주 서울 모임의 출발지를 미리 넣어두려 한다.
> 지도에 부산이 뜨고 "서울·경기 내 주소만 선택할 수 있어요"가 보이며 확정 버튼이 꺼져 있다.
> 지도를 서울로 끌어 옮기니 버튼이 켜진다.

## 4. 범위

### 이번에 만드는 것

`spec-fixed.md` §9의 INV-03-B-F01 ~ F10.

### 만들지 않는 것 — 기능

`spec-fixed.md` §12 Out of Scope 전체. 특히 아래는 반복해 명시한다.

- **백그라운드 위치·연속 추적** — `watchPosition` 계열을 쓰지 않는다.
- **저장된 출발지 등록** — 확정한 현재 위치를 사용자 저장 장소로 만들지 않는다.
- **지도 위 임의 지점 탭 이동** — 핀은 중앙 고정이고 지도만 움직인다.
- **백엔드 API 추가·변경** — 역지오코딩 endpoint를 만들지 않는다.
- **1차 릴리스에서의 앱 지원** — `expo-location`·권한 문구·`OPEN_APP_SETTINGS`는 2차다.

### 만들지 않는 것 — 구조

ADR-1(안 C)이 레이어를 하나 더 두므로, **거기서 멈추는 선**을 함께 못박는다.
아래를 지금 만들면 재사용처가 하나뿐인 상태에서 추상화만 불어난다.

- **범용 지도 컴포넌트로 일반화하지 않는다.** `shared/ui/map-location-picker`는
  "중앙 핀 하나 + 카메라 idle" 그 이상을 하지 않는다. 다중 마커, 클러스터링,
  경로·폴리라인, 지도 위 장소 검색, 줌 컨트롤 커스터마이즈는 범위 밖이다.
- **지도 제공자 추상화 레이어를 만들지 않는다.** 카카오 SDK에 직접 의존한다.
  구글·네이버로 갈아끼울 수 있는 인터페이스를 지금 설계하지 않는다.
- **picker 상태를 전역 스토어로 올리지 않는다.** 열림 상태는 URL이, 좌표·주소는
  지역 훅이 소유한다. Zustand 스토어를 추가하지 않는다.
- **좌표를 캐싱하거나 세션에 보존하지 않는다.** 새로고침하면 처음부터 다시 요청한다.
  "직전에 쓴 현재 위치" 같은 기억을 만들지 않는다.
- **`DepartureDraft`에 필드를 추가하지 않는다.** `accuracy`나 좌표 출처(`검색`/`현재위치`)를
  타입에 심지 않는다. 서버 계약이 받지 않는 값이고, 화면 안내는 지역 상태로 충분하다.

## 5. 기술 결정 (ADR)

### ADR-1. 위치 확인 화면의 FSD 배치와 상태 소유

**Context**

`현재 위치로 찾기` 버튼은 `DepartureQuickSelect` 안에 있고, 이 컴포넌트는
`entities/place/ui/place-search-view.tsx`가 렌더한다. `PlaceSearchView`는 네 진입점이
공유한다 — 모임장 위저드(`features/meeting/create-meeting`), 참여자 응답
(`_pages/invite-participation`), 응답 수정(`_pages/meeting-edit-response`),
마이페이지(placeholder).

`PlaceSearchView`가 `entities`에 있는 것은 우연이 아니다. `departure-draft.ts`에 이유가
기록돼 있다 — **features끼리는 서로 import할 수 없어서**, `create-meeting`에 두면 게스트
흐름이 쓸 수 없다. picker의 배치도 같은 규칙의 지배를 받는다.

동시에 이 화면은 성격이 다른 두 가지를 한꺼번에 다룬다.

- **기술 요소**: 카카오 SDK 로드, 지도 렌더링, 카메라 `idle` 감지, 중앙 핀 고정.
  좌표만 알면 되고 출발지·모임이라는 개념이 필요 없다.
- **도메인 로직**: 역지오코딩 결과를 `DepartureDraft`로 변환, 지원 지역(서울·경기) 판정,
  CTA 활성 조건, INV-03 복귀.

**Decision**

두 성격을 레이어로 가른다.

```
shared/ui/map-location-picker/          지도 + 중앙 고정 핀. props: center, onIdle(coords)
shared/lib/kakao-map-sdk.ts             sdk.js를 한 번만 주입하는 로더
shared/model/request-current-location.ts 브리지 요청 (request-pick-image.ts 옆)

entities/place/model/use-current-location.ts   좌표 어댑터 호출 + CurrentLocationResult 상태
entities/place/model/use-reverse-geocode.ts    핀 좌표 → 확정 주소
entities/place/model/to-supported-region.ts    지원 지역 판정 (순수 함수)
entities/place/ui/current-location-picker.tsx  위를 조립. DepartureDraft를 산출
entities/place/ui/place-search-view.tsx        isPickerOpen이면 위를 렌더 (수정)
```

- `shared/ui/map-location-picker`는 **좌표만 안다.** 주소도, 출발지도, 모임도 모른다.
- picker의 열림 상태는 컴포넌트 state가 아니라 **URL(`?picker=current`)** 이 소유한다
  (`spec-fixed.md` §4-1). 전역 스토어를 추가하지 않는다.
- 좌표·주소 상태는 `entities/place`의 훅이 지역 상태로 소유한다. 확정 전에는 어떤 스토어에도
  쓰지 않는다 — CTA를 누른 순간 기존 `onSelect` 계약을 타고 나간다.
- 좌표 요청 시작점은 `use-current-location.ts` **한 곳뿐이다.** A1(위치정보법)이 무너져
  동의 게이트가 필요해지면 여기 앞에 한 번만 끼운다.

**Alternatives**

- **안 A — `entities/place` 단일 슬라이스에 전부.**
  거부 이유: 지도 렌더링과 출발지 도메인이 한 컴포넌트에 섞여, 지도 동작을 테스트하려면
  카카오 SDK와 역지오코딩과 지원 지역 판정을 한꺼번에 모킹해야 한다. 파일 수는 적지만
  가장 검증하기 어려운 부분(지도 카메라)이 가장 모킹이 무거운 곳에 갇힌다.
  A와 C의 차이는 파일 위치가 아니라 **테스트 경계**다.

- **안 B — `features/place/pick-current-location`으로 분리하고 slot으로 주입.**
  거부 이유: FSD의 same-layer import 금지에 정면으로 걸린다.
  `features/meeting/create-meeting/ui/departure-search-route.tsx`가
  `features/place/*`를 import할 수 없어, 주입 지점이 모임장은 app route, 참여자는 `_pages`로
  갈린다. 진입점 네 곳에 같은 배선을 반복해야 하고 한 곳을 빠뜨리면 그 진입점에서만
  버튼이 조용히 죽는다. steiger가 CI에서 잡아주지도 못한다 — 배선 누락은 경계 위반이 아니라
  그냥 빠진 코드이기 때문이다.

**Consequences**

좋아지는 것:

- 지도 컴포넌트를 좌표 in / 좌표 out으로 단위 테스트할 수 있다. 도메인 모킹이 필요 없다.
- 지원 지역 판정이 순수 함수라 경계값(서울/경기/그 외/빈 응답)을 표로 테스트할 수 있다.
- `PlaceSearchView`가 직접 렌더하므로 **네 진입점이 배선 없이 자동으로 동작한다.**
- FSD 의존 방향이 `entities → shared` 하나뿐이라 steiger를 그대로 통과한다.

나빠지는 것 — 이쪽을 감수하고 고른 것이다:

- **파일과 경계가 하나 더 늘어난다.** 안 A보다 초기 구현량이 많고, 지도 props를 바꿀 때
  두 레이어를 함께 손대야 한다.
- **재사용처가 아직 하나뿐이다.** `shared/ui/map-location-picker`는 지금 `current-location-picker`
  단 한 곳에서만 쓰인다. "모임 장소 확정 화면에서 재사용할 수 있다"는 것은 가능성이지
  요구사항이 아니다. 조기 추상화로 판명될 위험을 인정한다.
- **`shared`가 카카오에 직접 의존한다.** 제공자 교체를 위한 추상화 레이어는 만들지 않기로
  했으므로(§4), 지도 제공자를 바꾸면 `shared/ui/map-location-picker` 내부를 고쳐야 한다.
  이름에 `kakao`를 넣지 않은 것은 그때 인터페이스를 유지하기 위해서지, 교체가 공짜라는 뜻이 아니다.
- **A2가 무너지면 `shared` 프리미티브가 통째로 무의미해진다.** 지도를 못 쓰는 것으로
  판명되면 안 A보다 버릴 코드가 많다. 그래서 스파이크 S1이 구현 이슈보다 앞선다.

### ADR-2. 이미 확정된 결정 (Stage 1)

Stage 1 인터뷰에서 확정한 아래 4건은 `spec-fixed.md`에 근거와 함께 기록돼 있다.
ADR 형식으로 다시 쓰지 않고 참조한다.

| 결정                                                | 위치                  |
| --------------------------------------------------- | --------------------- |
| 좌표 획득 = 네이티브 브리지 + 브라우저 폴백         | `spec-fixed.md` §5-1  |
| 지도·역지오코딩 = 카카오 지도 Web SDK               | `spec-fixed.md` §6-1  |

## 6. 용어 정의

`spec-fixed.md` §3과 동기화한다. 이 문서에서 추가로 쓰는 용어만 적는다.

| 용어            | 정의                                                                     |
| --------------- | ------------------------------------------------------------------------ |
| **picker**      | 위치 확인 화면(INV-03-B)의 코드상 이름. `?picker=current`의 그 picker다. |
| **좌표 어댑터** | 실행 환경에 따라 브리지 또는 `navigator.geolocation`을 고르는 함수.      |
| **SDK 로더**    | 카카오 지도 `sdk.js`를 한 번만 주입하고 `kakao.maps`를 돌려주는 유틸.    |

## 7. 검증 기준

이슈 분해 시 AC로 옮길 항목이다. `spec-fixed.md` §9의 "놓치기 쉬운 지점"을 포함한다.

- [ ] `현재 위치로 찾기`를 누르면 URL에 `?picker=current`가 붙는다.
- [ ] 좌표 획득 성공 시 지도 중심이 그 좌표이고 핀이 중앙에 있다.
- [ ] 지도를 끄는 동안 CTA가 비활성이고, 멈추면 새 좌표의 주소로 갱신된다.
- [ ] CTA를 누르면 INV-03에 출발지가 채워져 있고 검색 화면이 남아 있지 않다.
- [ ] CTA로 확정한 `departure`의 `latitude`/`longitude`가 **핀 좌표**다(현재 좌표가 아니다).
- [ ] 뒤로가기 4경로 모두 검색 화면으로 가고 출발지가 변경되지 않는다.
- [ ] picker가 열린 상태의 뒤로가기 핸들러가 `true`를 반환해 검색 화면이 함께 닫히지 않는다.
- [ ] 지원 지역 밖이면 CTA가 비활성이고, 지도를 서울·경기로 옮기면 **다시 활성화된다**.
- [ ] 현재 위치 재정렬이 좌표를 재요청하지 않는다(권한 팝업이 다시 뜨지 않는다).
- [ ] 권한 거부·차단·서비스 꺼짐·timeout·알 수 없는 실패가 각각 다른 안내로 구분된다.
- [ ] 모든 실패 상태에서 검색 화면으로 돌아갈 수 있다.
- [ ] 도로명 주소가 없는 좌표에서 지번 주소로 확정할 수 있다.
- [ ] `name`에 `현재 위치` 같은 고정 문자열이 들어가지 않는다.
- [ ] 1차 릴리스 빌드에서 네이티브 컨텍스트면 `현재 위치로 찾기`가 렌더되지 않는다.
