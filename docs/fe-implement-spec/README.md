# 프론트엔드 화면 구현 명세 규격

`fe-implement-spec` 아래의 문서는 기획, Figma, 확정된 라우트와 API 계약을 한곳에서 대조하기
위한 프론트엔드 화면 구현 명세다. 모임 생성(CRT), 초대·참여(INV), 홈(HOME), 모임 현황(VIEW)
등 화면 영역과 관계없이 같은 규격을 사용한다.

## 작성 원칙

- 최신 기능 명세를 기준으로 작성한다.
- Figma 이미지는 문서와 같은 화면 폴더에 두고 상대 경로로 첨부한다.
- 실제 `app` 디렉터리에 존재하는 경로만 확정 라우트로 기록한다.
- Orval 생성 코드는 화면에서 조회·표시·입력·전송하는 데이터의 필드명과 제약을 확인하는
  근거로만 사용한다.
- 서버 요청 시점, 전역 상태 도구, 컴포넌트 구조 등 화면 기획으로 확정되지 않은 구현 설계는 다루지 않는다.
- PNG를 기준으로 픽셀값을 역산하거나 `flex`, `grid` 같은 CSS 구현 방식을 지정하지 않는다.
- 요소의 순서, 정렬, 화면 하단 고정 여부, 선택·비활성 표현처럼 이미지에서 관찰 가능한 레이아웃 규칙은
  기록한다.
- 정확한 간격, 크기, 색상과 타이포그래피는 Figma Dev Mode 또는 디자인 토큰을 구현 기준으로 삼는다.
- 기획, Figma, 라우트와 API 계약이 다르면 임의로 결정하지 않고 `확인 필요`에 기록한다.
- `UI States`, `API 영향`, `State`, `Frontend 후보`, `Component 후보` 섹션은 만들지 않는다.

## 문서 구성

모든 화면 문서는 아래 순서와 제목을 사용한다.

1. `화면 개요`
2. `근거 자료`
3. `기능 명세`
4. `라우트 및 화면 이동`
5. `화면 사용 데이터`
6. `Figma 화면`
7. `기능별 동작`
8. `검증 기준`
9. `확인 필요`

### 화면 개요

화면 ID, 화면명, 경로, 진입 화면, 다음 화면을 표로 기록하고 화면 목적을 한 문장으로 작성한다.

### 근거 자료

검토에 사용한 최신 기획의 기준일, Figma 이미지, 실제 라우트 파일, Orval 생성 스키마를 상대 링크로
기록한다.

### 기능 명세

기획에서 전달된 표의 열과 내용을 유지한다.

| 구분 | 기능 ID | 기능명 | 설명 | 참고 | 우선순위 | 상태 | 완료 | 제외 | 수정일 |
| ---- | ------- | ------ | ---- | ---- | -------- | ---- | ---- | ---- | ------ |

### 라우트 및 화면 이동

확정된 URL과 사용자 동작에 따른 이동 목적지를 기록한다. 후보 라우트나 구현 제안은 넣지 않는다.

### 화면 사용 데이터

화면이 API·경로·세션에서 받아 표시하거나 분기에 사용하는 값과, 사용자가 입력해 요청으로 보내는
값을 기록한다. 화면 용어, 출처 또는 API 필드, 필수 여부, 용도·제약, 값이 없을 때의 처리를 표로
정리한다. 이 화면에서 사용하지 않는 필드는 넣지 않는다.

입력이 없는 조회·완료 화면은 “사용자 입력 없음”을 명시하고 표시·분기 데이터만 기록한다.

### Figma 화면

첨부 이미지를 문서에 직접 표시하고, 각 이미지가 나타내는 화면과 핵심 차이를 짧게 적는다.

### 기능별 동작

기능 ID 단위로 노출 조건, 사용자 입력, 활성화 조건과 이동 결과를 기록한다.

### 검증 기준

구현 완료 여부를 확인할 수 있는 관찰 가능한 결과만 체크리스트로 작성한다.

### 확인 필요

근거 자료 사이의 충돌이나 구현 전에 기획 결정이 필요한 내용만 기록한다. 미확정 사항이 없으면
`없음`으로 표시한다.
