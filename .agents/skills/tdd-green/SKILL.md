# TDD Green

실패 테스트를 사양으로 삼아 구현 코드만 최소 변경한다. 목표는 설계를 확장하는 것이 아니라 모든 Red를 추적 가능한 순서로 Green으로 바꾸는 것이다.

## 필수 원칙

- `*.test.ts`와 `*.test.tsx`를 수정하지 않는다. 테스트가 잘못됐다고 판단되면 멈추고 근거를 보고한다.
- 한 번에 실패 테스트 하나만 선택해 최소 구현하고 재실행한다.
- 테스트에 없는 기능, 선행 추상화, 임의의 디자인을 추가하지 않는다.
- 기존 Green 회귀를 즉시 수정한다.
- 같은 실패에 대한 수정·재실행은 최대 5회다. 원인을 모른 채 두 번 실패하면 먼저 진단한다.
- 시그니처와 완료 조건은 해당 `docs/features/**/issue-{N}.md`를 정본으로 삼는다.
- UI 작업은 `docs/design-system/README.md`와 관련 컴포넌트·foundation 문서를 먼저 읽는다. 문서에 없는 시각 요소는 발명하지 않는다.
- 저장소 `AGENTS.md`와 사용자 지침이 이 스킬보다 우선한다.

## 입력 해석

사용자가 이슈 번호를 명시하면 해당 번호를 쓴다. 명시하지 않았지만 현재 브랜치가 `feat/#N/...`이고 단일 `issue-N.md`가 작업과 명확히 대응하면 N을 사용한다. 둘 이상 후보가 있으면 사용자에게 묻는다.

## 워크플로

### 1. 상태와 사양 확인

1. 브랜치, staged/unstaged/untracked 파일을 확인한다.
2. 기존 사용자 변경을 보존한다. 부분 staging은 테스트 실행을 방해하지 않으면 그대로 둔다.
3. 해당 `issue-{N}.md` 전체를 읽고 테스트 시나리오 수를 센다.
4. 구현 대상이 UI면 디자인 시스템 문서를 읽는다.

### 2. 실패 목록 수집

먼저 이번 이슈 범위의 테스트를 실행한다.

```bash
pnpm --filter @repo/web exec vitest run --project unit <관련 테스트 경로들>
```

테스트 파일 import 자체가 실패해 시나리오가 수집되지 않으면 issue 문서의 확정 시그니처와 일치하는 stub만 만든다.

```ts
export function example(): never {
  throw new Error('not implemented');
}
```

문서 시나리오 수보다 Vitest의 전체 Tests 수가 적으면 collect 누락을 먼저 해결한다.

### 3. 실패 하나씩 Green으로 전환

각 실패에 대해 반복한다.

1. 가장 위의 실패 하나를 선택한다.
2. 단언을 통과시키는 최소 구현만 작성한다.
3. 해당 단일 테스트를 실행한다.

```bash
pnpm --filter @repo/web exec vitest run --project unit <테스트 파일> -t "테스트 이름"
```

4. 목표가 통과하면 관련 slice 테스트를 실행해 회귀를 확인한다.
5. 통과한 시나리오 한 줄만 issue 문서에서 `[x]`로 바꾼다.
6. 다음 실패로 이동한다.

테스트를 통과시키려고 테스트 단언, selector, mock을 바꾸지 않는다. 환경 문제라면 구현을 비틀지 말고 검증 지점을 조정하거나 사용자에게 보고한다.

### 4. 최종 검증

관련 시나리오가 모두 통과하면 다음 순서로 검증한다.

1. 관련 slice 테스트
2. `pnpm --filter @repo/web check-types`
3. 관련 파일 lint 또는 프로젝트 lint
4. FSD 변경이 있으면 `pnpm --filter @repo/web lint:steiger`
5. 전체 테스트 `pnpm test`
6. 가능하면 `pnpm --filter @repo/web exec vitest run --coverage`

커버리지를 올리기 위해 Green 단계에서 테스트를 추가하지 않는다. 미커버 분기가 누락 시나리오로 의심되면 보고만 한다.

### 5. 결과 보고

- 통과 시나리오 수 / 전체 수
- 수정하거나 생성한 구현 파일
- 실행한 검증과 결과
- 커버리지와 누락 의심 분기
- 5회 안에 해결하지 못한 실패와 이유
- 후속으로 분리할 사항

## 금지 사항

- 테스트 수정
- 여러 Red를 겨냥한 큰 선행 구현
- 테스트가 요구하지 않는 옵션·분기·헬퍼 추가
- 디자인 토큰 대신 색상 하드코딩
- 전체 테스트를 매 반복마다 실행하기
- 타입 검사를 생략하고 Vitest 통과만으로 완료 선언하기
